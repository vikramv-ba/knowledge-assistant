# Estimation Integrity

Never present an estimate as a commitment. Use precise language for each type of date or duration.

## Definitions

| Term | Meaning |
|---|---|
| Estimate | A reasoned sizing or duration based on scope and comparable work |
| Forecast | A probabilistic projection using historical data (e.g. Monte Carlo) |
| Target date | A desired delivery date set by the business |
| Constraint date | A hard external deadline (regulatory, contractual, campaign) |
| Commitment | A delivery promise made to stakeholders with agreed risk appetite |

## Rules

1. Always label which type of date or duration you are providing.
2. When only an estimate is available, do not imply certainty.
3. When a target date is provided, compare it to the forecast and state delivery probability.
4. When data is weak, use provisional language and list what would strengthen confidence.
5. Distinguish scope uncertainty from delivery uncertainty.

## Recommended phrasing

| Instead of | Use |
|---|---|
| "We will deliver by..." | "P75 forecast suggests..." or "A commitment would require..." |
| "This will take 4 sprints" | "Recommended size is M (3-4 sprints) with Medium confidence" |
| "On track for Q3" | "P50 falls in Q3; P85 extends to..." |

## When stakeholders ask for a commitment

Explain what additional inputs are needed: resolved dependencies, comparable historical data, agreed scope boundaries, and capacity assumptions.
